# Democrate Website — Bug Bounty & Audit Report

## Executive Summary
The `democrate` platform is a functional full-stack anonymous complaint system, but it has **multiple critical security vulnerabilities**, **state management bugs**, **accessibility violations**, and **missing mobile navigation** that need immediate attention before any production deployment.

## 2. Frontend UX/UI & Functional Problems

### Critical Functional Bugs
1. **Mobile Navigation Missing** — Navbar uses `hidden md:flex`; on mobile there is **no hamburger menu** to navigate after login
2. **Full Page Reloads After Mutations** — `teacher_dashboard.js` and `admin_dashboard.js` call `window.location.reload()` after actions, destroying SPA state and causing flicker
3. **Dual Auth Storage Mismatch** — `state.js` stores session under `democrate_session`, while `auth.js` uses `democrate_jwt` + `democrate_user`. After reload, auth can break if one key is missing
4. **Toast Container Duplication Risk** — `index.html` already has `#toast-container`, but `components.js` defines `ToastContainer()` that would inject a second one

### High-Impact UX Issues
1. **Inline `<style>` in JS Templates** — `complaint_form.js` and `register.js` inject `<style>` tags inside HTML strings; invalid in some parsers
2. **Global Scope Pollution** — `window.appLogout`, `window.showToast` leak into global namespace
3. **Inconsistent Auth References** — Some views use `Auth.getCurrentUser()`, others `state.user`, others destructured `user`; after reload these can be stale/missing
4. **Non-Functional UI Elements** — Search/filter dropdowns on leaderboard, "Load More" buttons, "Generate Report" admin button all exist but have no handlers

### Accessibility Violations (WCAG)
1. **Missing ARIA Labels** — Icon-only buttons (upvote, downvote, visibility toggles, star ratings) lack `aria-label`
2. **Unassociated Labels** — `<label>` elements lack `for` attributes matching input `id`s
3. **No Skip Navigation** — Keyboard users cannot bypass the fixed nav bar
4. **No Focus Management** — No focus restoration after route changes; no focus trapping in modals/popups
5. **No `aria-live` Regions** — Toasts and dynamic status updates are not announced to screen readers
6. **Color Contrast Risk** — Text over glassmorphism backgrounds may fail WCAG AA depending on backdrop-filter rendering
7. **Keyboard Navigation Gaps** — Star ratings and tag toggles rely on mouse clicks only
8. **Generic Alt Text** — Logo is `alt="Logo"`, preview images are `alt="Preview"`

### Performance Issues
1. **Tailwind CDN in Production** — CDN script is large, not cacheable, adds significant parse/compile time
2. **No Component Memoization** — Every route change replaces `innerHTML` and re-fetches all data
3. **No Caching Layer** — Every mount hits the server for complaints/leaderboard
4. **Expensive `backdrop-filter`** — `glass.css` applies blur on every card; GPU-heavy on mobile/low-end devices
5. **Mesh Gradient + Fixed Attachment** — `background-attachment: fixed` with 7 radial gradients causes repaint jank on mobile
6. **External Avatar Dependencies** — `randomuser.me` and `ui-avatars.com` images load slowly and fail offline
7. **No Lazy Loading** — All view modules are eagerly imported in `app.js`
8. **No Skeleton Loading** — `Components.SkeletonCard()` exists but is never used

## 3. Enhancement Recommendations

### Immediate (Security Blockers)
1. **Restrict Admin Registration** — Remove `role=Role.ADMIN` from public `/auth/register`; default to `STUDENT`
2. **Move JWT Secret to Environment** — `SECRET_KEY = os.getenv("SECRET_KEY")` with startup validation
3. **Fix Anonymity Leak** — Replace deterministic `Anon-{id[:3]}X` with a random unlinkable ID stored in a separate mapping table
4. **Add Database Constraints** — Unique constraint on `(complaint_id, user_id)` for votes; unique on `(teacher_id, student_id)` for ratings
5. **Enforce State Machine** — Add explicit state transition validation in verify, archive, and vote endpoints
6. **Implement Rate Limiting** — Add `slowapi` or reverse-proxy rate limiting on auth endpoints

### Short-Term (UX & Stability)
1. **Fix Mobile Navigation** — Add a hamburger menu that toggles the nav links on `hidden md:flex` elements
2. **Replace Reloads with State Updates** — After verify/reject/archive, update local state and re-render instead of `window.location.reload()`
3. **Unify Auth Storage** — Standardize on one storage key (`democrate_session`) and ensure `loadSession()` rehydrates all state correctly
4. **Remove Toast Container Duplication** — Ensure `ToastContainer()` is only instantiated once
5. **Add Self-Vote Check** — Block users from voting on their own complaints
6. **Constrain Rating Values** — Pydantic `Field(ge=1, le=5)` + DB check constraint
7. **Audit All Error Responses** — Remove sensitive fields (`details`, internal IDs) from public API responses

### Medium-Term (Quality & Performance)
1. **Migrate to Build Pipeline** — Add Vite or Webpack; replace Tailwind CDN with PostCSS build
2. **Add Pagination** — Replace unbounded `limit` with cursor-based pagination (max 100 per page)
3. **Implement Refresh Tokens** — Reduce access token TTL to 15-30 min; add rotating refresh tokens
4. **Upgrade Password Hashing** — Switch from `sha256_crypt` to `bcrypt` with work factor 12
5. **Add Password Complexity** — Enforce min 8 chars, mixed case, numbers, symbols
6. **Add `is_active` Flag** — Allow disabling accounts without deletion
7. **Populate AuditLog** — Log all sensitive actions (login, vote, verify, admin actions) with user_id, action, target, timestamp, IP
8. **Add Lazy Loading** — Split view modules into dynamic imports
9. **Implement Caching** — Cache leaderboard and public complaints with short TTL (30-60s)
10. **Glassmorphism Fallbacks** — Add solid background fallbacks for `backdrop-filter` on low-end/mobile browsers

### Long-Term (World-Class Polish)
1. **Real-Time Updates** — WebSocket or Server-Sent Events for live leaderboard/vote updates
2. **Dark Mode Toggle** — Implement the already-configured `darkMode: "class"` toggle
3. **Notification System** — Build UI for the existing `state.notifications` array
4. **Search & Filter** — Wire up existing but non-functional search/filter UI components
5. **Edit/Delete Complaint** — Allow students to edit within a time window
6. **Analytics Dashboard** — Admin analytics with charts (complaints by category, trends over time)
7. **Voice/Image Upload** — Implement the roadmap features (voice complaints, evidence uploads)
8. **Offline Resilience** — Service worker + IndexedDB for offline complaint drafting

Email authentication is a good addition to the roadmap. It improves account security, reduces fake registrations, and provides a recovery path for forgotten passwords. Since you're waiting for school approval before adding more features, it fits well as an "Upcoming Feature."

I'd describe it like this:

---

# Upcoming Feature: Email Authentication & Account Verification

### Purpose

Enhance account security by verifying that every registered user owns the email address they provide.

### Features

* **Email Verification**

  * Users receive a one-time verification link or OTP during registration.
  * Accounts remain inactive until the email is verified.

* **Password Reset**

  * Users can securely reset forgotten passwords using a time-limited email link or OTP.

* **Account Recovery**

  * Verified email addresses can be used to recover access if a password is forgotten.

* **Security Alerts**

  * Notify users by email about important account events such as:

    * New login from an unfamiliar device.
    * Password changes.
    * Email address changes.

* **Administrative Notifications (Optional)**

  * Administrators can receive email notifications for high-priority events, such as complaints requiring immediate attention.

### Planned Workflow

```text
User Registration
        │
        ▼
Enter Email Address
        │
        ▼
Verification Email Sent
        │
        ▼
User Clicks Verification Link
        │
        ▼
Account Activated
```

### Benefits

* Prevents fake or mistyped email addresses.
* Makes password recovery straightforward.
* Improves overall account security.
* Builds user trust in the platform.

### Planned Implementation

* FastAPI backend
* Secure verification tokens with expiration
* SMTP email service (or a transactional email provider in the future)
* Time-limited verification and password reset links
* Database fields to track email verification status
